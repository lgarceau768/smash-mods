Why it can't mix with the roster

Its binaries load at process start, outside ARCropolis's control, and it rewrites cast-wide params the vanilla-built added characters inherit. It also patches the hid system module (title 0100000000000013) — deploy.sh installs and removes that patch correctly when switching.

The two walls

Both measured on this hardware, not folklore. Every profile above is shaped by them.

Plugin cap — an OS constraint

Each mod's plugin.nro is chainloaded via nn::ro::LoadModule; the OS allows 64 modules per process, shared with the game itself and the fighter code it loads mid-match.

34th plugin ⇒ dies at boot  ·  30 = safe ceiling

Verified twice with different mods in position 34. The linter hard-errors past 33. Merged packs (CHAO5: 10 characters, 1 plugin) are the only way to more characters.

Memory — mostly exonerated

The boot death once blamed on file-count OOM occurred on a build that was also over the plugin cap (35) with two raw file conflicts. With those fixed, ~75k files boots and plays — no file-count ceiling has actually been hit yet.

75k files ⇒ boots at 30 plugins

The bisect kit (toggle_mods.sh, pre-balanced halves) stays ready for the day a real memory wall appears. RAM OC to 1600 MHz steadies loading.

Rules that keep it alive: offline / local play only (DNS-MITM + 90DNS, re-applied per network) · ARCropolis auto-update off (its update host isn't Nintendo's, so DNS blocking doesn't stop it) · never let the console update Smash — the entire stack is pinned to 13.0.4.
